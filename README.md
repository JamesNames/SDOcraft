# SDOcraft

Один `SDOcraft.exe` для игрока. Minecraft 1.20.1, Forge 47.4.0, Java, моды и фото скачиваются через интернет. Сервер `93.119.104.217:25587` закреплён в коде. Русский интерфейс показывает только ник и пароль.

## Запуск

Скачать `SDOcraft.exe` из последнего обычного релиза, заменить старый EXE и нажать **«Играть»**. При первом запуске нужен интернет. Уже скачанные файлы проверяются, повторно загружаются только отсутствующие или повреждённые.

Перед каждым запуском в `options.txt` выставляются `lang:ru_ru` (русский язык) и `guiScale:2` (масштаб интерфейса 2). Остальные настройки игры сохраняются. После старта процесса Minecraft лаунчер закрывается, игра продолжает работать самостоятельно. Если процесс завершается в первые две секунды, окно остаётся открытым с сообщением об ошибке. Кнопка «Восстановить» игру не запускает и окно не закрывает.

После закрытия лаунчера ошибки Minecraft можно посмотреть в `minecraft/game-output.log` или `minecraft/logs/latest.log`.

Данные игры: `%APPDATA%\SDOcraft\minecraft`. Фото: `%APPDATA%\SDOcraft\assets`. Настройки: `%APPDATA%\SDOcraft\settings.json`. По умолчанию выделяется 4 ГБ памяти; поле `ram` можно изменить в JSON при закрытом лаунчере.

## Maxstuff

Сборка v1.3.2 включает `maxstuff-legacy-1.8.3_hotfix.jar`. Он скачивается напрямую с официального проекта автора на Modrinth. Размер и SHA-256 должны совпадать с файлом, использованным при подготовке сборки. Необходимые EndlessAmmo 2.0 и TaCZ 1.1.8 уже входят в сборку.

Перед запуском Minecraft лаунчер извлекает папку `assets/maxstuff/gunpack/maxstuff` из JAR в `%APPDATA%\SDOcraft\minecraft\tacz\maxstuff`. В ней находятся модели, текстуры, значки и данные оружия. Все файлы пакета проверяются по размеру и CRC из проверенного JAR; целая папка остаётся без изменений. При повреждении новая папка сначала полностью распаковывается, затем заменяет старую. Предыдущая копия сохраняется в `mod-backups`, а ошибка замены вызывает откат. Другие оружейные пакеты не затрагиваются.

**«Проверить сборку»** проверяет также извлечённые ресурсы. **«Играть»** и **«Восстановить»** восстанавливают их. Восстановление использует ресурсы исходного мода: отсутствующие в самом моде изображения оно не создаёт.

## Обновления через GitHub

Лаунчер получает `modpack.json` из последнего публичного релиза. Фото загружается при открытии, моды — после нажатия «Играть». Файлы сначала загружаются во временную папку, проходят проверку размера и SHA-256, затем устанавливаются. Заменённые и удалённые управляемые моды сохраняются в `mod-backups`. При ошибке выполняется откат. Посторонние моды не удаляются; другая версия того же мода обнаруживается как конфликт.

Если GitHub временно недоступен, можно использовать сохранённый список и полностью установленную сборку. Обновляются файлы сборки; сам EXE автоматически не заменяется.

В репозитории находятся `release/modpack.json` и `release/notes.md`. После успешной сборки Windows workflow публикует подготовленный релиз, если его тег `v` + `VERSION` из `config.py` ещё не существует. Версия в манифесте должна совпадать. Уже опубликованные версии этот шаг не перезаписывает. Релиз сначала создаётся как черновик, затем к нему прикрепляются проверенный EXE и манифест, и только после этого он публикуется.

В v1.3.2 ссылки на прежние 10 модов и фото ведут в v1.3.0. **Не удаляйте релиз v1.3.0 и его файлы.** Maxstuff скачивается с Modrinth; вручную загружать его на GitHub не нужно.

## Подготовка другой сборки

На ПК с Python 3.12:

```console
python tools/prepare_release.py --mods C:\MyPack\mods --photo C:\MyPack\squad.webp --output release-assets --tag v1.3.3
```

Папка результата должна быть пустой. Создать обычный релиз с точно таким же тегом и прикрепить все подготовленные файлы из папки, включая `modpack.json`. ZIP целиком не прикреплять. Релиз не должен быть предварительным, чтобы работало `releases/latest`. После публикации workflow соберёт и прикрепит EXE.

Для автоматической публикации из `release/modpack.json` все ссылки в нём должны уже вести на доступные файлы. Сначала подготовить и проверить ресурсы; затем обновить манифест, заметки и `VERSION`. Не менять JAR после вычисления контрольных сумм.

## Пароль

Это пароль серверной команды `/login`. Вход по нику без авторизации Microsoft. Нажать «Скопировать /login» перед запуском игры, пока окно лаунчера открыто. В игре открыть чат → Ctrl+V → Enter. Пароль не записывается в файлы лаунчера, но команда попадает в системный буфер обмена.

## Сборка и проверки

Установить Python 3.12 на Windows и запустить `BUILD_EXE.bat`. Результат — `dist/SDOcraft.exe`. Альтернатива: **Actions → Build SDOcraft EXE → Run workflow**, артефакт **SDOcraft-Windows**. Моды, Java, Minecraft и фотография в EXE не входят.

`python -m unittest discover -s tests -v` проверяет загрузку, SHA-256, выборочное восстановление, резервные копии, обрыв сети, откат, распаковку Maxstuff, защиту путей, сохранение настроек и работу процесса игры после выхода лаунчера. Полный запуск Minecraft, отображение предметов и подключение к серверу проверяются на ПК игрока. Работа TLSkinCape в собственном лаунчере не подтверждена.

Иконка: `branding/sdocraft.ico` для Windows и `branding/sdocraft.png` для интерфейса. Оба файла входят в EXE.

Неофициальный лаунчер, не связан с Mojang или Microsoft.
