# SDOcraft

Один `SDOcraft.exe` для гравця. Minecraft 1.20.1, Forge 47.4.0, Java, моди й фото завантажуються через інтернет. Сервер `93.119.104.217:25587` зафіксований у коді. Інтерфейс показує лише нік і пароль.

## Перший реліз — для власника

1. Відкрити **Releases → Create a new release**.
2. Створити тег **v1.3.0**, вибрати гілку `main`.
3. Розпакувати наданий архів `SDOcraft_Release_Assets_v1.3.0.zip`.
4. Прикріпити **усі 12 файлів** з його папки: `modpack.json`, `squad.webp`, `mod-01.jar` … `mod-10.jar`. ZIP цілком не прикріплювати.
5. Натиснути **Publish release**. Реліз має бути звичайним, не Draft і не Pre-release, щоб працювало посилання `releases/latest`.
6. У вкладці **Actions** дочекатися успішної збірки **Build SDOcraft EXE**. Вона додасть `SDOcraft.exe` до релізу. Якщо для репозиторію ввімкнені незмінні релізи, завантажити `.exe` з Actions і додати його до чернетки релізу перед публікацією.

Гравцям передавати лише `SDOcraft.exe`. Без прикріплених 12 файлів перший запуск не зможе встановити збірку.

## Як це працює

Лаунчер отримує `modpack.json` з останнього публічного релізу. Фото завантажується під час відкриття, моди — після натискання «Грати». Перевіряються розмір і SHA-256; завантажуються лише відсутні або змінені файли. Спочатку завантажуються всі необхідні файли в тимчасову папку, потім встановлюються. Попередні змінені/видалені керовані моди зберігаються в `mod-backups`. Сторонні моди не видаляються. Якщо встановлення не вдається, попередні файли відновлюються.

Якщо GitHub тимчасово недоступний, можна використати раніше завантажений список і повністю встановлену збірку. Перший запуск потребує інтернету. Оновлюються файли збірки; сам `.exe` автоматично не замінюється.

Дані гри: `%APPDATA%\SDOcraft\minecraft`. Фото: `%APPDATA%\SDOcraft\assets`. Налаштування: `%APPDATA%\SDOcraft\settings.json`. Пам’ять за замовчуванням — 4 ГБ; поле `ram` можна змінити в цьому JSON при закритому лаунчері.

## Пароль

Це пароль серверної команди `/login`. Вхід за ніком без Microsoft-авторизації. Кнопка «Скопіювати /login» копіює команду з паролем; у грі відкрити чат → Ctrl+V → Enter. Автоматичного входу немає. Пароль не записується у файли лаунчера, але команда потрапляє в системний буфер обміну.

## Наступні оновлення збірки

На ПК із Python 3.12:

```console
python tools/prepare_release.py --mods C:\MyPack\mods --photo C:\MyPack\squad.webp --output release-assets --tag v1.3.1
```

Папка результату має бути порожньою. Створити новий звичайний реліз з ТОЧНО таким самим тегом і прикріпити всі згенеровані файли. Перш ніж публікувати, перевірити збірку в Minecraft. Не змінювати файли `.jar` після створення `modpack.json`: контрольні суми перестануть збігатися.

## Зібрати exe вручну

Встановити Python 3.12 на Windows. Запустити `BUILD_EXE.bat`. Результат — `dist/SDOcraft.exe`. У `.exe` немає модів, Java, Minecraft чи фотографії; вони завантажуються окремо. Альтернатива: **Actions → Build SDOcraft EXE → Run workflow**, потім завантажити артефакт **SDOcraft-Windows**.

## Перевірки й обмеження

`python -m unittest discover -s tests -v` перевіряє початкове встановлення, повторний запуск без скачування, вибіркове відновлення, SHA-256, резервні копії, обрив мережі, відкат і обмеження шляхів. Повний запуск Minecraft і підключення до сервера потребують перевірки на ПК гравця. Поведінку TLSkinCape у власному лаунчері не підтверджено.

Неофіційний лаунчер, не пов’язаний із Mojang або Microsoft.

## Іконка

Лаунчер використовує власний оливковий щит із літерою S. `branding/sdocraft.ico` містить розміри від 16 до 256 px для Windows, а `branding/sdocraft.png` — зображення для інтерфейсу. Обидва файли входять до `.exe`; окремо завантажувати їх не потрібно.
